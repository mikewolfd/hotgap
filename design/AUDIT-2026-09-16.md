# Design system audit — 2026-09-16

Scope: `design/README.md`, `tokens.css`, `inventory.md`, `charts.md` and the three
surface sketches, rendered in Chromium (Playwright) at 390px and 1280px, light and
dark, plus the caseworker print path. Screenshots are under `design/audit/`. The
pages were compared against the data as it stands today: `core/data/summary.json`
generated 2026-09-16 (11 archetypes, a per-state `coverage` block, no
`childcareSubsidyUnmodeled` field), and the live CLI output for the same Colorado
household the sketches render (`npm run -s hotgap -- curve --state CO --kids 3,7
--earnings 38000 --offline --json`, run through the project's own runner).

Contrast figures below were computed from the hex values in `tokens.css` with the
WCAG 2.x relative-luminance formula, not read off the screen.

## How the data moved under the sketches

Same household, sketch versus today's CLI:

| | sketch (sweep 2026-09-15) | today |
|---|---|---|
| net at $38,000 | $67,000 | $84,371, of which $29,379 is the child-care subsidy |
| largest drop | $9,390 at $54k→$55k | $25,449 at $54k→$55k |
| danger zones | one, $36k–$86k | four: $6k–$10k, $26k–$30k, $36k–$45k, $46k–$119k |
| the household's zone ends | $86,000 (raise $48,000) | $45,000 (raise $7,000) |
| safe exit / leap | $86,000 / $48,000 | $119,000 / $73,000 |
| deferred cliffs | one (CHIP at $72k) | none |
| `summary.childcareSubsidyUnmodeled` | 23 states | field absent (every state now pays a paying archetype somewhere) |
| archetypes | 8 | 11 (three dual-earner couples added — the household the child-care cliff actually hits) |
| per-state `coverage` block | — | corrections, unmodeled programs, labelled `otherBenefits`, vintages, model version |

None of that is a fault of the sketches — they are frozen to one sweep on purpose —
but it means the audit can ask a sharper question than "is it pretty": does the
system have a *place* for each of these facts? Several it does not.

## Blockers

### B1. The "not computed" treatment is keyed to a field that no longer exists, and the mark itself is invisible

- **Where:** `journalist.html:288` and `caseworker.html:368` (two different
  hard-coded `UNMODELED` lists, 18 states and 23 states); `tokens.css`
  `.hg-hatch-grey`; `README.md` § "We cannot compute this"; `charts.md` § 2.
- **What I saw:** `summary.json` today has no `childcareSubsidyUnmodeled` key
  (`core/src/data.ts:43` makes it optional and the pipeline omits it when empty).
  The pages, the README and `charts.md` all still say "23 states" as present
  fact, and the two pages disagree with each other about which states. The
  self-healing claim ("read from the file every render") is true of the design
  intent and false of both sketches.
  Separately, the grey hatch measures **1.29:1** in light (`--rule` #D3D8DE on
  `--surface-sunk` #F1F3F6) and **1.2:1** in dark. On a 40px desktop tile it is a
  faint texture (`audit/journalist-1280-light-map.png`); on a 24px phone tile it
  is a light-grey square (`audit/journalist-390-light-map-legend.png`). Worse,
  its mean luminance sits *outside the ramp on the "small" side* in both modes:
  lighter than `--loss-1` in light, darker than dark-mode `--loss-1` in dark. A
  greyscale print or a CMS-compressed screenshot sorts the hatched states as
  "lower than the lowest bin" — precisely the misreading the README says this
  mark exists to prevent.
- **Who it hurts:** the journalist, whose one forbidden sentence ("Texas is
  gentler") is what a faint hatch invites; the caseworker, whose coverage line
  currently prints a stale count.
- **Smallest fix:** (1) Key `IncompleteMarker` off
  `coverage[state].unmodeled[]` — present for every state today, and it is where
  `coverage.ts:103` puts the child-care gap when the optional field returns — so
  the treatment also covers the two states whose premium program is unmodeled
  (NJ Health Plan Savings, WA Cascade Care Savings). Render the count; delete
  every typed "23". (2) Change the hatch to `--ink-3` stripes on `--surface-sunk`
  (5.1:1 light, 6.0:1 dark) at a 2px/6px pitch; that puts its mean luminance
  mid-ramp in both modes and makes the *pattern* legible, which is the channel
  that survives greyscale.

### B2. Printing from dark mode produces an unreadable client sheet

- **Where:** `caseworker.html:124-130` (`@media print`), `tokens.css` dark
  blocks.
- **What I saw:** with `data-theme="dark"` and print media emulated, `body`
  becomes white/black but every token stays dark: the readout, the key, the
  ledger's "Who" column and every `--ink-2`/`--ink-3` caption print near-white
  on white; the selected drop row prints as a black bar with invisible text; the
  breakdown panel and "What this model does not include" print as dark boxes;
  the current-earnings diamond (`fill: var(--ink)` = #F2F5F7) vanishes.
  `audit/caseworker-1280-print-from-dark.png`.
- **Who it hurts:** the caseworker — "Print the client sheet" is the single
  artefact the client leaves the office with — and, downstream, the citizen who
  is handed it.
- **Smallest fix:** in `tokens.css`, add `@media print { :root, :root[data-theme]
  { color-scheme: light; …light values… } }` after the dark blocks. The file
  already carries the dark set twice; the light set should be the one defined
  once and reasserted for print. Then delete the page-level `body { color:#000 }`
  override, which is what half-fixed it and hid the rest.

### B3. The data now says which HotGap correction produced each number, and the design has nowhere to put it

- **Where:** `inventory.md` (no component), `caseworker.html:310-324` ("What
  this model does not include" — hand-typed), `journalist.html:225-273` ("How
  these numbers were made" — global prose, not per state), `SourceNote` (#17).
- **What I saw:** `coverage[state].corrections` carries five entries per state
  with `applies`, `source` and a one-sentence `note`: parent-Medicaid
  `policyOverrides` (7 states), `maTafdc` (MA), `premiumAssistance` (modeled 5 /
  ladder 2 / none 44), `childcareSubsidy` (`added by HotGap` in 28 states,
  `in net income` in 23), `coverageGap` (10 non-expansion states). Plus
  `unmodeled[]`, `otherBenefits[]` (NJ ANCHOR, $450) and `vintages` (child-care
  price is `county 2015` for CO, `county 2012` for DC, a national median for IN
  and NM; reach uses the 5-year PUMS in 10 states; `model.version` 2.5.0).
  Nothing on any surface renders any of it. The caseworker page's ledger
  footnote says "No state $0-premium wrap applies" for Colorado while the data
  says `premiumAssistance.source: "modeled"` (Colorado premium assistance,
  $1,656 max, netted out of the premium). The caseworker source line cites the
  DOL child-care database without the year; for Colorado that is a 2015 price
  inflated eleven years by the ECI, which a caseworker defending "$25,449" needs
  to be able to say.
- **Who it hurts:** the caseworker (a number without its correction is not
  defensible); the journalist (provenance is the whole ask, and "TX: parent
  limit overridden from the state handbook, coverage-gap correction on,
  child-care subsidy added by HotGap" is a paragraph of the story).
- **Smallest fix:** one new component, **CorrectionsApplied** — a list rendered
  from `coverage[state].corrections` filtered to `applies === true`, each row
  the program, the `source` word as a chip, and the `note` as the cite line
  (same shape as `ThresholdLedger`'s cite). It sits under the verdict on the
  caseworker page and under the map on the journalist page, scoped to the
  selected state. Extend `SourceNote` to take `vintages` and `model` so it
  prints "child-care price: county 2015 · ACS 2024 1-yr · policyengine-us
  2.5.0" from the data rather than from copy.

### B4. "No cliff" is rendered as a value of $0 and it moves the scale; a null safe exit without the flag breaks the tile

- **Where:** `journalist.html:324-338, 386-390, 442-455`; `charts.md` § 2
  "Three tile states".
- **What I saw:** with "1 adult, no children" and "Safe exit", Wisconsin's row
  is `[0,0,0,0,0,0,0]` — no cliff of $200 or more anywhere — and the page shades
  it the lightest bin, ranks it last as "$0", prints "Safe exit: $0" in the
  table, and lets it set the bin floor to $0, so every other state is squeezed
  into the top bins ("Bins: five equal-width steps from $0 to $76,000").
  `audit/journalist-1280-light-childless-safe-exit.png`. Today's summary has
  eleven such cells (New Mexico alone has eight). `charts.md` names three tile
  states; a fourth — *no cliff found* — is a real, common outcome and it is the
  best news on the map, not a small number.
  Also: `isPastAxis` keys only on `leapIsLowerBound`, but two cells today (NE
  single-1 and single-2) have `safeExit: null` with the flag `false`. On the
  "Safe exit" measure the tile path calls `b.index(null)` → `NaN` →
  `var(--loss-NaN)` → an unshaded tile with no title. The sketch masks this
  because NE is in its hard-coded unmodeled list; with that list gone it shows.
- **Who it hurts:** the journalist, twice — a false "$0" in the copy-out table
  and a distorted scale.
- **Smallest fix:** treat `cliffCount === 0` as a fourth tile state — no fill,
  solid `--rule-strong` outline, reads *no cliff*, its own legend entry, its own
  block under the ranking ("No cliff found (N)"), excluded from the bins, and
  the table prints "none" not "$0" for width, leap and exit. Make `past` true
  whenever the plotted value is `null`, not only when the flag is set.

## Should fix

### S1. The caseworker scenario bar is a 349px sticky header on a phone (125px on desktop)

`caseworker.html:20-35`. At 390px the eleven chips wrap to seven rows and stay
pinned, leaving 495px of an 844px viewport; the verdict starts at y=349
(`audit/caseworker-390-light.png`, `audit/caseworker-390-light-drops.png`). And
the bar shows nine of the household's inputs while `HouseholdAnswers` now has
status, years in the US, savings, self-employment, hours, spouse earnings,
disability and employer coverage — adding those makes it worse. Fix: sticky
only the wordmark and the two actions; the input chips collapse to a single
summary line ("CO · El Paso · 1 adult, kids 3 & 7 · $38,000 · edit") below
720px, and group the rest behind *edit*. Decide, in `inventory.md`, what a
value chip does when pressed — today the first six are `<button>`s with no
stated behaviour and no `aria-pressed`.

### S2. `all: unset` removes the focus ring on 62 buttons

`caseworker.html:80` (`.drop-btn`) and `journalist.html:116` (`.rowbtn`). Both
declare `all: unset`, which resets `outline`, and both come after `tokens.css`,
so the `:focus-visible` rule loses. Measured: computed `outline-style: none`
on every drop row (11) and every state row (51) while focused. `tokens.css`
promises "Focus is never removed and never invisible." Fix: replace `all: unset`
with the four properties actually being reset (`border:0; background:none;
padding:0; font:inherit`).

### S3. Map-tile labels on bin 3 fail AA

`journalist.html:389` switches to `--surface` ink at bin index ≥ 3. On bin 2
(`--loss-3`) the label is `--ink` at **3.24:1** light, **2.92:1** dark, at 9–12px.
Switching at index ≥ 2 gives 5.37:1 / 5.41:1. One character to change.

### S4. "Show the numbers" has no disclosure affordance

`citizen.html:65` sets `summary { display: flex }`, which drops the `::marker`
in Chromium (measured `content: normal`); the control renders as a heading
(`audit/citizen-1280-light.png`). Fix: `display: list-item` with the flex
layout on an inner span, or draw the marker with `::before`.

### S5. The same threshold is $54,000 in one place and $55,000 in two others on the same page

`caseworker.html:255` (ledger: "$54,000 CCDF child care subsidy"), `:168`
(tile: "at $54,000 → $55,000") and `:332` (handout: "The biggest drop is at
$55,000 of pay"). The citizen page says $55,000. The data's `programEnds` uses
the landing point for SNAP ($54,000 for a $53k→$54k step) and the start point
for child care ($54,000 for a $54k→$55k step), so the sketch faithfully rendered
an inconsistency in core — but the design has no stated convention either. Fix:
state one rule in `inventory.md` for `ThresholdLedger`/`StepList` ("a program
ends at the first pay at which it is gone") and render the ledger from the
cliff list so both surfaces derive it; file the `programEnds` asymmetry against
`core/src/escape.ts` separately.

### S6. The citizen's "you keep" is not believable and its assumptions are hidden

`citizen.html:110-116`. Today the sentence would read "You are paid $38,000. You
keep $84,371." Of that, $29,379 is a subsidy paid to a day-care provider that
never passes through the household, and the sub-line ("help and tax money are
part of it") does not say so. The page also never states what it assumed: rent
$1,735/mo (HUD FMR), child care $1,438/mo, SNAP/Medicaid/WIC taken up, subsidy
claimed, citizen, no savings — all of which the caseworker bar shows and the
citizen cannot see. Fix: under the answer, one line naming the largest non-cash
component ("$29,379 of this is child-care help paid straight to your day care"),
rendered from `curve.points[i].programs.childcare`; and a short "What we
assumed about you" list in the same register as `StepList`, from `answers`.
The footer's "We do not ask about where you were born, what you own" is now
false for the live path (`--status`, `--savings`); say what is assumed instead.

### S7. The leap has no mark, and the curve has no rule for more than one zone

`charts.md` § 1. The system's named derived quantity — the leap — is never drawn:
the band shows the zone, the reference line shows the peak, and the leap
(exit − current) is left to be inferred as a horizontal gap. Today's curve has
four zones, with the household's own (`personal.zone`, ends $45k) nested in a
wider worst one (`escape`, exits $119k); `charts.md` says "band", singular, and
`AnswerSentence` has one slot, so it is undefined which number the citizen is
told. Fix: in `charts.md`, the band is `personal.zone`; the safe exit is a
second vertical rule labelled *safe from here*; the leap is a bracket along the
reference line from the diamond to the exit, direct-labelled once, and it is
the second figure the sentence names.

### S8. Cliff marks collide

`caseworker.html:458-471`. Eleven cliffs on a $150k axis put six dots within
68px and three within 12px (x = 255, 263, 267); on the citizen crop the $53k
and $54k dots overlap (`audit/citizen-390-light-chart.png`,
`audit/caseworker-1280-light.png`). The direct label "−$9,390" sits inside the
cluster. Fix: a collision rule in `charts.md` — dots closer than 10px merge into
one mark with a count, and the ledger row is where they separate.

### S9. Drop rows are 61–88px tall and the earnings text floats

`caseworker.html:80` sets `line-height: var(--touch)` on the row button; a
wrapped label ("$26k →" / "$27k" at 390px) becomes 88px, and because sibling
cells are `vertical-align: top` the earnings sit 8–15px below the drop value
(`audit/caseworker-390-light-drops.png`). Fix: `min-height: var(--touch)`
with `display:flex; align-items:center` on the button and `vertical-align:
middle` on the row, and `white-space: nowrap` on the earnings cell.

### S10. The archetype list is hard-coded to eight; the data has eleven

`journalist.html:147-156, 293-295`. The three `married-dual-*` archetypes are
absent, and per the repo README they are "the household the child-care cliff
actually hits". There is no label field in `summary.archetypes`, so a label rule
is a design decision: render from `married`, `childAges` and the id suffix
("2 adults, both working, 2 children (3 and 7)"). While there, drop "eight
household shapes" from the lede.

### S11. Control boundaries are below the non-text contrast floor

`--rule-strong` (#AEB7C0) is the only boundary on the scenario chips (1.96:1 on
`--surface`), the filter `<select>`s (1.96:1) and the CSV button. WCAG 1.4.11
wants 3:1 for a control's visible boundary when it is the only indicator. Fix:
a `--control-edge` token at ≥3:1 on both grounds (light `#7C8894` measures
3.49:1 on `--surface`, 3.02:1 on `--plane`), used only for interactive edges;
leave `--rule` for table hairlines.

### S12. Interactive charts are announced as images; `aria-selected` on `<tr>`

`citizen.html:129`, `caseworker.html:182`: `role="img"` on a `tabindex="0"`
wrapper that answers arrow keys. A screen reader announces an image and does not
expect keys. Use `role="group"` with `aria-roledescription="interactive chart"`
and keep the long `aria-label`. `caseworker.html:528` sets `aria-selected` on a
`<tr>` in a plain table; it is only valid under `role="grid"`/`row`. Use
`aria-current="true"` on the button instead.

### S13. Drift between `tokens.css`, `inventory.md` and the pages

- `DeferredBadge` (#10) is declared twice (`citizen.html:76`, `caseworker.html:82`)
  with different gap and padding, and the journalist page — tagged J — has no
  badge, only a count column. `AnswerSentence` is tagged W but the caseworker
  verdict has no keyed underlines; `StatTile` is tagged J but the journalist page
  has no tiles.
- Used but not inventoried: the **Callout** (`.note` blue rule on citizen,
  `.caution` amber rule on journalist, `.coverage` swatch-plus-line on
  caseworker — three shapes for one job), **Button** (three declarations:
  `.theme-btn`, `.act .chip`, `.dl button`), **FilterRow**, **SkipLink**.
- `tokens.css` exports five shared classes; `.key`, `.readout`, `.skip`,
  `.theme-btn`, `.panel` (padding `--s4` on one page, `--s5` on the other),
  `.scroll-x`, the table base and `caption` are re-declared per page.
- Motion: `citizen.html:444` hard-codes `duration: 700` and the easing instead
  of reading `--dur-draw`/`--ease`, so the "one place to honour
  reduced-motion" is bypassed (the page re-checks `matchMedia` itself).
- Type: SVG tick labels are 11px (`caseworker.html:429,433`) and 12px against a
  stated 13px floor for prose-like labels.
- The caseworker ledger's CCDF cite (`caseworker.html:256-259`) is a paragraph
  of design-author reasoning ("Two upstream gaps exist elsewhere and are
  different problems…"), not a footnote a caseworker would read out.

Smallest fix: move the badge, key, readout, callout, button, skip link, table
base and panel into `tokens.css` as `hg-*` classes (it already has the pattern),
delete the page copies, correct the three persona tags, and add Callout, Button
and FilterRow to the inventory or fold them into an existing row.

### S14. The ghost caption is unconditional; the y-range obligation is unenforced

`caseworker.html:208-211` always says "the real curve including the deferred
drop is the dashed ghost", but the ghost is drawn only when the deferred drop
exceeds 1.5% of the y-range; here ($219 on $67k) it is not drawn, so the caption
describes a mark that is absent. `charts.md` § "Axis honesty" requires the
visible y-range to be ≥2.5× the largest drop; the citizen crop computes its
floor from the window slice with 14% padding and would give ≈1.3× on today's
$25,449 drop. Fix: render the ghost sentence from the same condition, and widen
the citizen window or the y padding until the ratio holds.

  Say "frozen to" rather than "render".

## What is good and should be kept

- **The thesis.** One primitive (a step) read at three resolutions, and the
  explicit decision about *what each surface leaves implicit*. This is the
  right spine for a multi-persona system and it should not be revisited.
- **Magnitude, not virtue.** The single-hue plum loss ramp, validated in both
  modes, with no good/bad status pair anywhere. `--note` and `--caution`
  describe the data. Keep exactly this.
- **The lift.** `charts.md`'s rule that the plotted line must have deferred
  drops lifted out, with the ghost for the real curve, is the one thing here
  that is easiest to get wrong and it is written down and implemented in both
  sketches.
- **Solid = this year, dashed = later** across chart, chip and table; the
  diamond for position; the hollow dot for a deferred cliff. Shape and pattern
  carry meaning, so it survives greyscale.
- **Readout instead of tooltip**, keyboard stepping on the curve, and a table
  twin for every chart. The `aria-live` readout works (verified with arrow keys).
- **Axis honesty**: the y-floor is rendered from the computed value; bins are
  recomputed per measure and their bounds are printed; the tile cartogram with
  equal squares and the rank strip on a shared non-zero axis.
- **The provenance line inside every figure box**, and the CSV that carries
  its own provenance columns.
- **The citizen crop** to a window around the household, and the Flesch-Kincaid
  gate on the citizen copy.
- **Type and voice**: one family, sentence case, no eyebrows, no icons, panels
  as rule-and-ground with `--r-panel: 0`. The pages do not read as a template.
- **The print handout** as a five-sentence client sheet.

## Verdict

The foundation is sound and should be built on, but not yet. `tokens.css`, the
thesis in the README and the chart grammar in `charts.md` are careful,
measured, and better reasoned than most shipped design systems; nothing in the
palette, type or layout needs rethinking. What blocks a UI build is that the
data moved and the design did not follow: the one honesty mechanism the system
is proudest of (the hatched "not computed" state) is keyed to a field that has
gone, is invisible at its current contrast, and misorders in greyscale; the
`coverage` block — corrections, vintages, model version — has no component at
all; "no cliff" is rendered as $0 and distorts the scale; and the caseworker's
print sheet is unreadable from dark mode. All four are bounded: one new
component, one new tile state, one hatch colour, one print token block. With
those and S1–S5 done — a few days, not a sprint — the system is ready, and the
first UI should be the caseworker surface, because it is the one whose
numbers have to be defended and the one that exercises every component.
